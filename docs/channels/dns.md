# DNS: исправление отклонённых карточек

Для существующего товара обработчик сначала получает актуальную стадию через
`GET /api/v1beta1/products/{id}`. При `stage = Rejected` использует ресурс
`/api/v1beta1/products/{id}/rejection-correction`; для остальных стадий сохраняет
обычную последовательность обновления `/uniform`.

Исправление отклонённого товара выполняется в два запроса:

1. `GET /api/v1beta1/products/{id}/rejection-correction` получает `editRevision`.
2. `PUT` по тому же пути передаёт ревизию в обязательном заголовке
   `If-Product-Rejection-Correction-Revision`.

PUT полностью заменяет `specOptionValues`, `media` и `mainPhotoUrl` значениями,
полученными из актуального маппинга PIM. Характеристики и медиа, отсутствующие
в отправленном наборе, не сохраняются автоматически. Название, штрихкод и поля
MDM не входят в этот запрос: API отклоняет такие поля, их изменение относится
к отдельному ресурсу `/mdm`. Описание и документы, отсутствующие в запросе,
сохраняются по контракту DNS.

После успешного исправления канал устанавливает `status = 4`,
`dnsError = false`, `dnsNeedsResubmission = true` и показывает:

> Исправления сохранены в DNS. Отправьте товар на повторную модерацию в личном кабинете DNS.

Статус `4` здесь означает ожидание следующего шага, а не подтверждённую отправку
на модерацию. PUT сам не отправляет отклонённую карточку повторно; по сообщению
поддержки DNS это нужно сделать в личном кабинете, в том числе массовым выбором
товаров. Пока синхронизация видит `Rejected`, сообщение сохраняется. Когда она
видит другую стадию, признак сбрасывается и применяется обычная обработка
статуса DNS. Непустой `errorKind` у отклонённого товара также сбрасывает признак:
ошибка DNS отображается вместо сообщения о сохранённых исправлениях.

При ошибке чтения статуса, чтения ресурса или PUT обработчик сообщает ошибку.
При отсутствующей ревизии PUT не выполняется. Конфликт ревизии не приводит к
повторной записи поверх изменившегося ресурса: необходимо повторить выгрузку
с новым чтением. Эмуляция читает актуальную стадию существующего товара и
показывает соответствующий PUT, но не выполняет запись и не устанавливает
признак сохранённых исправлений.

Если замечание модерации относится к полю «Модель», проверьте его маппинг:
исправление применяется, когда модель передаётся в `specOptionValues` как
характеристика категории. Изменение только `#name` этим запросом не отправляется.

## Проверка

Из каталога `server`:

```powershell
node -r ts-node/register/transpile-only --test tests/dns-rejection-correction.test.cjs
node node_modules/typescript/bin/tsc -p . --noEmit
```

Тесты запускают настоящий обработчик, подменяя внешний транспорт DNS и загрузку
метаданных категории. Реальный запрос на сохранение товара и ручная
перемодерация в кабинете этими тестами не проверяются.
