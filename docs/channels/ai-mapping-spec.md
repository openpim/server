# Спецификация AI-маппинга атрибутов OpenPIM

Версия: 1.0. Дата: 2026-10-08.

Документ описывает реализованный сценарий для маркетплейсов. Расширение для мастер-каталога описано отдельно как следующий этап, который ещё не реализован.

## 1. Цель

По нажатию кнопки предложить соответствия между атрибутами выбранной категории маркетплейса и существующими атрибутами OpenPIM. Пользователь проверяет предложения, применяет выбранные строки и сохраняет настройки канала.

Пример: «Цвет» маркетплейса → `product_color` в OpenPIM.

Функция не генерирует значения характеристик товаров, не создаёт атрибуты, не формирует выражения JavaScript и не публикует товары. Результат нейросети считается предложением, требующим проверки.

## 2. Поддерживаемые каналы

| Канал | Тип | Статус |
| --- | --- | --- |
| Wildberries | 2 | Поддерживается |
| Ozon | 3 | Поддерживается |
| Яндекс Маркет | 9 | Поддерживается |
| Мастер-каталог / MDM | 6 | AI-маппинг пока не подключён |

Интерфейс реализован в `web3`. Для использования требуется обновить сервер и интерфейс.

## 3. Пользовательский сценарий

1. Администратор задаёт провайдера, адрес API, модель и ключ в серверном `.env`, включает функцию и перезапускает сервер.
2. Пользователь открывает настройки поддерживаемого канала и выбирает категорию.
3. Интерфейс проверяет доступность AI-маппинга и наличие пустых строк.
4. Пользователь нажимает кнопку заполнения с помощью AI. Во время запроса отображается индикатор загрузки, повторный запуск блокируется.
5. Сервер загружает актуальные характеристики категории, подбирает кандидатов OpenPIM и запрашивает предложения у модели.
6. Интерфейс показывает таблицу: характеристика маркетплейса, предложенный атрибут OpenPIM, пояснение и выбор строки для применения.
7. Прямые соответствия без признака проверки выбраны изначально. Соответствия, требующие проверки, пользователь выбирает самостоятельно. Строки без допустимого соответствия применить нельзя.
8. Пользователь применяет выбранные предложения. Изменения появляются в редакторе, но ещё не сохранены на сервере.
9. Пользователь проверяет результат и сохраняет канал обычной кнопкой сохранения.
10. При необходимости пользователь отменяет последнее AI-применение. Последующие ручные изменения не откатываются. Для сохранения отмены необходимо снова сохранить канал.

Для одной характеристики доступна отдельная кнопка с волшебной палочкой справа от поля атрибута OpenPIM. Она запрашивает только ID выбранной пустой строки и использует тот же диалог проверки и обычное сохранение канала. Одиночный запрос доступен и при более чем 200 пустых строках категории; заполненные строки не перезаписываются.

## 4. Правила заполнения

- Заполняются только строки, в которых пусты и `attrIdent`, и `expr`.
- Существующие соответствия и выражения не перезаписываются.
- Служебные поля с идентификатором, начинающимся на `#`, исключаются.
- Строки с повторяющимся идентификатором характеристики исключаются из запроса интерфейса.
- Изменяется только `attrIdent`; параметры маппинга, выражения и флаги источников обновления сохраняются.
- Для языковых атрибутов используется полный идентификатор с суффиксом языка: например, `product_name#ru`.
- Для WB/Ozon применение и отмена выставляют `category.changed = true`, сохраняя существующий `readingTime`.
- Если категория, язык или канал изменились во время запроса, интерфейс не применяет устаревший результат.
- Перед применением повторно проверяются допустимость кандидата, пустота строки и совпадение текущей строки со снимком до запроса.
- Отмена восстанавливает только строки, которые после AI-применения не были изменены или удалены.

## 5. Подготовка данных для модели

Сервер использует характеристики из существующего обработчика канала, а не доверяет перечню характеристик, переданному браузером.

Для характеристики передаются идентификатор, название, ограниченное описание, обязательность, признаки словаря и числового типа. Для кандидатов OpenPIM передаются `attrIdent`, название, группа, тип и признак словаря.

Кандидаты формируются из видимых групп атрибутов, имеющих применимые типы объектов. Если категория задаёт `valid`, используется этот список; иначе используется `channel.valid`.

При сохранённом `category.visible` сервер дополнительно учитывает пути выбранных корней и их поддеревьев. Для `visibleRelation` загружаются также другие входящие источники тех же товаров на этой связи. Атрибуты, доступные на предках этих путей, остаются кандидатами. Обычные атрибуты исключительно этой связи фильтруются по `attr.visible`; атрибуты других/нескольких связей и стандартные поля товара сохраняются при неопределённом контексте. Без `category.visible` фильтра по путям нет. Подробности: [фильтр видимости](../ai-mapping/visibility-filter.md).

Для каждой характеристики выбираются до 30 кандидатов. Ранжирование учитывает точное совпадение названия, общие слова, идентификатор, группу и признак словаря. Это лексический поиск: полезное соответствие с необычным синонимом может не попасть в список.

Не передаются ключи маркетплейсов, заголовки их запросов, полная конфигурация канала и значения товаров. Названия и описания каталога передаются выбранному внешнему провайдеру.

После top-30 запрос обогащается ограниченными вариантами справочников: до восьми локализованных подписей по 80 символов, статус доступности, известный размер и признак усечения. PIM-кандидаты получают расшифровку типа и признак числового поля; словарность определяется type=7, а не одной ссылкой lov. Для общего LOV передаётся число ссылающихся атрибутов; его примеры не гарантируют допустимость значений конкретного поля. Яндекс использует inline param.values и явное имя единицы; Ozon — ограниченную первую страницу; для отсутствующего источника сохраняется unavailable. Данные товаров не используются. Полные правила и проверки: [контекст вариантов](../ai-mapping/value-context.md).

Большие LLM-пакеты автоматически уменьшаются без удаления контекста строк. Загрузка marketplace-словарей ограничена отдельным окном 10 с, до 5 с на вызов и 20 вызовами. Чтение LOV ограничено 200 уникальными справочниками и tenant.

## 6. Контракт ответа модели

```json
{
  "suggestions": [
    {
      "id": "85",
      "attrIdent": "product_color",
      "needsReview": false,
      "reason": "Совпадают название и назначение характеристики"
    },
    {
      "id": "999",
      "attrIdent": null,
      "needsReview": true,
      "reason": "Однозначное соответствие не найдено"
    }
  ]
}
```

`id` — идентификатор запрошенной характеристики. `attrIdent` — точный идентификатор из её списка кандидатов или JSON `null`. `needsReview` — логическое значение. `reason` — строка с кратким пояснением; сервер ограничивает её 600 символами.

Модель должна использовать смысл характеристики и кандидатов, не выполнять инструкции из метаданных и возвращать `null`, если однозначного соответствия нет.

## 7. Проверка результата

| Ситуация | Поведение |
| --- | --- |
| Идентификатор PIM точно входит в список кандидатов строки | Предложение принимается |
| Идентификатор PIM выдуман, изменён или взят из чужого списка | Строка возвращается с `attrIdent = null`, `needsReview = true` и пояснением; остальные корректные строки сохраняются |
| Строка пропущена моделью | Возвращается пустое соответствие, требующее проверки |
| У характеристики нет кандидатов | Запрос модели для неё не выполняется; возвращается пустое соответствие |
| Неизвестный ID характеристики или повтор ID в ответе | Весь запрос отклоняется |
| Неверные типы полей, некорректный JSON, отказ или незавершённый ответ | Весь запрос отклоняется |
| Ошибка провайдера или таймаут любого пакета | Весь запрос отклоняется; частичный результат в интерфейс не возвращается |

Числовые характеристики, словарные соответствия и кандидаты типов 3, 4, 9 требуют проверки независимо от флага модели. Различия единиц измерения, словарей и назначения полей проверяет пользователь. Применение соответствия не выполняет преобразование значений.

## 8. Настройки сервера

| Переменная | Значение и ограничение |
| --- | --- |
| `OPENPIM_AI_MAPPING_ENABLED` | Включение только значением `true`; по умолчанию выключено |
| `OPENPIM_AI_PROVIDER` | `openai` или `openai-compatible`; по умолчанию `openai` |
| `OPENPIM_AI_BASE_URL` | Базовый URL API; транспорт добавляет `/chat/completions`. Для совместимого провайдера обязателен |
| `OPENPIM_AI_API_KEY` | Ключ Bearer; для `openai` обязателен. Хранится только на сервере |
| `OPENPIM_AI_MODEL` | Обязательный идентификатор модели провайдера |
| `OPENPIM_AI_RESPONSE_FORMAT` | `json_schema` по умолчанию или `json_object`; проверка сервера работает в обоих режимах |
| `OPENPIM_AI_TIMEOUT_MS` | Общий бюджет всех LLM-пакетов: 1–300000 мс, значение по умолчанию в коде 60000 |
| `OPENPIM_AI_MAPPING_BATCH_SIZE` | 1–30 характеристик на пакет, значение по умолчанию в коде 20 |
| `OPENPIM_AI_USE_SYSTEM_CA` | По умолчанию выключено. При `true` добавляет доверенные системные сертификаты к сертификатам Node.js для AI-запросов |

Рабочая настройка для текущего испытания OpenAI-совместимого сервиса:

```dotenv
OPENPIM_AI_MAPPING_ENABLED=true
OPENPIM_AI_PROVIDER=openai-compatible
OPENPIM_AI_BASE_URL=https://example.com/v1
OPENPIM_AI_API_KEY=replace-with-server-secret
OPENPIM_AI_MODEL=replace-with-provider-model
OPENPIM_AI_RESPONSE_FORMAT=json_object
OPENPIM_AI_TIMEOUT_MS=300000
OPENPIM_AI_MAPPING_BATCH_SIZE=5
OPENPIM_AI_USE_SYSTEM_CA=false
```

Это пример без реальных секретов. Системное хранилище сертификатов включается при необходимости и требует Node.js с `tls.getCACertificates`. Проверка HTTPS-сертификатов остаётся включённой. После изменения `.env` требуется перезапуск сервера.

## 9. Ограничения и доступ

- За операцию обрабатывается от 1 до 200 запрошенных характеристик.
- Пакеты выполняются последовательно в рамках одного общего лимита времени.
- Сериализованный вход одного пакета ограничен 200000 символами; HTTP-ответ — 1 МБ.
- HTTP-переадресации провайдера запрещены.
- Требуются авторизация, права редактирования конфигурации каналов и права просмотра/редактирования выбранного канала.
- Канал, языки и атрибуты берутся из текущего tenant.
- Одновременно разрешён один запрос AI-маппинга на tenant в пределах процесса сервера. Между несколькими процессами блокировка не общая.
- Серверный запрос предложений не сохраняет маппинг. Сохранение выполняется обычным механизмом обновления канала.
- Сырой ответ провайдера не выводится в сообщения транспортных ошибок.

## 10. API и компоненты

GraphQL-запрос доступности:

```graphql
getChannelAIMappingStatus(channelId: ID!): ChannelAIMappingStatus!
```

GraphQL-мутация получения предложений:

```graphql
suggestChannelAttributeMappings(
  channelId: ID!
  categoryId: ID!
  mappingKey: String!
  language: String!
  attributeIds: [ID!]!
): [ChannelAIMappingSuggestion!]!
```

Основные места реализации относительно корня рабочего пространства:

- `server/src/channels/ai/access.ts`: права доступа, tenant, актуальные метаданные и блокировка.
- `server/src/channels/ai/mapping.ts`: конфигурация, кандидаты, проверка ответа и пакеты.
- `server/src/channels/ai/provider.ts`: запрос к OpenAI-совместимому API, HTTPS и таймаут.
- `server/schema/channels.graphql`, `server/src/resolvers/channels.ts`: GraphQL-контракт и обработчики.
- `web3/src/channels/AIMappingAssistant.vue`: кнопка, запрос и таблица предложений.
- `web3/src/channels/aiMapping.mjs`: применение и отмена.
- `web3/src/channels/MappingAttributesComponent.vue`: интеграция в редактор.

## 11. Критерии приёмки реализованного этапа

- [ ] В поддерживаемом канале с доступными правами пользователь получает предложения для выбранной категории.
- [ ] Существующие соответствия, выражения и параметры остаются без изменений.
- [ ] Разрешённые прямые соответствия применяются только после действия пользователя.
- [ ] Недопустимый PIM-идентификатор не применяется и не скрывает корректные предложения других строк.
- [ ] Числовые и словарные соответствия требуют явного выбора пользователя.
- [ ] Смена категории или языка исключает применение устаревшего ответа.
- [ ] Ручное изменение строки во время запроса исключает её AI-применение.
- [ ] Отмена сохраняет последующие ручные изменения.
- [ ] Таймаут и ошибки API не изменяют сохранённый маппинг.
- [ ] Нельзя получить данные другого tenant или обойти права канала.
- [ ] Ключи API не передаются браузеру или внутри метаданных модели.
- [ ] Серверные и клиентские тесты проходят, TypeScript-проверка и сборка интерфейса успешны.
- [ ] Проведён ручной прогон на реальной категории с проверкой соответствий. Синтетический запрос подтверждает работу транспорта, но не качество на реальном каталоге.

## 12. Следующий этап: мастер-каталог

Для экрана MDM требуется отдельное расширение: сопоставлять атрибуты товаров поставщика с существующими атрибутами мастер-каталога выбранной категории.

Нужно добавить серверный источник кандидатов, учитывающий настройки типов поставщика, типов мастер-продуктов, связи категорий и области видимости атрибутов. Простого включения кнопки для типа 6 недостаточно: текущий сервер получает исходные характеристики через обработчики маркетплейсов.

Расширение должно использовать существующего провайдера из `.env` и сохранять правила проверки, подтверждения, заполнения только пустых строк и отмены. Проверочный сценарий: выбрать категорию в канале мастер-каталога, запросить соответствия «атрибут поставщика → атрибут мастер-каталога», применить выбранные и сохранить канал.

Этот этап не входит в текущее реализованное покрытие. Точный контракт MDM и его тесты необходимо определить при реализации.
