## Реализация

- `buildMappingCandidatePools` использует существующие фильтры групп, типов и видимости, но возвращает весь доступный пул. `buildMappingRequests` сохраняет прежний scoring и первые 30. Embeddings нельзя строить только из прежнего shortlist, если цель — проверить полноту поиска.
- Semantic retrieval: нормализация векторов, cosine similarity по полному переданному пулу, стабильное разрешение равенства по identifier.
- Hybrid: равновесное reciprocal-rank fusion двух списков (`k=60`), сохранение exact-name совпадений впереди, удаление дубликатов, максимум 30.
- Текст вектора содержит только выбранные метаданные: имя, identifier, группу, тип и описание; запрос характеристики также содержит категорию. Товары, API headers, секреты и выражения в embedding-текст не включаются.
- Ollama-клиент принимает только HTTP loopback origin, проверяет установленную embedding capability и отсутствие remote-model fields. Cloud tags/remote URLs запрещены. API `/api/embed` вызывается с `truncate:false`; ошибки не приводят к скрытому обрезанию текста или lexical fallback в эксперименте.
- Кэш разделён по scope/tenant, языку, origin, модели, digest установленной модели, версии текста и хэшу метаданных. Изменение этих данных даёт новый ключ. Для нового экземпляра клиента provenance перечитывается; эксперимент фиксирует digest на время прогона.
- Лимиты: timeout60s на запрос по умолчанию, batch16 (макс.32), до6000 символов на текст, response8MiB, до4096 измерений, до4M компонентов итоговых векторов на вызов. Кэш ограничен30MiB в компактном JSON/20 000 записей и вытесняет старые записи. Reader принимает32MiB. Получаемые результаты текущего вызова сохраняются независимо от вытеснения кэша.

API и модель проверены по первичным источникам: [Ollama `/api/embed`](https://docs.ollama.com/api/embed), [BGE-M3](https://ollama.com/library/bge-m3). Используется dense-вектор API; sparse/ColBERT возможности BGE-M3 не подключены.

## Ручная проверка

Откройте [таблицу проверки](embeddings-review.html). В ней доступны три варианта top-5, полный список кандидатов для строки, поиск, фильтры, поле identifier и комментарий. Выбор источника остаётся черновиком до «Подтвердить». Изменение подтверждённой строки возвращает её в pending. Черновики сохраняются в браузере по хэшу dataset; кнопка «Сохранить JSON» экспортирует dataset с метками. Browser UI проверен: переход между строками сохраняет неутверждённый ввод; тестовые поля очищены, все144 строки оставлены pending.

Сначала лучше проверять строки, где методы расходятся. Подтверждайте смысл источника, отдельно отмечайте conversion и неоднозначность. «Нет соответствия» требует проверки контекста, а не только первых пяти предложений. Можно указать identifier вне показанного пула: это фиксирует пропуск отбора. Старый сохранённый `reference` — подсказка для проверки, не эталон.

Для полноценного Recall нужен полный снимок разрешённых групп/атрибутов и category visibility. Пользователь сообщил, что готового файла эталонов нет, поэтому метки формируются вручную. Подтверждение исторических строк само по себе не делает их пулы полными; инструмент намеренно не выдаёт quality metrics для неполного набора.

## Команды

Обновление таблицы от 13 октября: у характеристик и кандидатов показаны сохранённые примеры значений, тип и группа PIM. Примеры есть у 31 из 144 характеристик маркетплейса. Общие справочники и неполные выборки явно отмечены; значения общего справочника могут не относиться к конкретному атрибуту. Отсутствующие примеры не подменяются выдуманными. Эти данные используются только для отображения, не меняют embeddings или ранжирование. Добавление примеров сохраняет прежний ключ черновика браузера.

Для просмотра на постоянном локальном адресе запустите из `server`:

```powershell
node scripts/ai-mapping/serve-review.cjs
```

Страница доступна на `http://127.0.0.1:60712/`, пока процесс работает. Используйте тот же адрес, чтобы браузер видел прежние черновики.

Фильтрация PIM-значений исправлена 13 октября: SQL выбирает значения с `attrs`, содержащим ID конкретного атрибута, а также общие значения без ограничения (`attrs` отсутствует, null или пустой массив), как редактор LOV. Фильтр применяется до лимита восьми примеров и подсчёта total; кэш выборок разделён по справочнику и атрибуту. Tenant и deletedAt проверяются для обоих объектов. Для этой проверки актуализированы примеры 285 PIM-атрибутов; рейтинги остались историческими. Общие значения, включая технические строки в данных, остаются разрешёнными согласно настройкам справочника. Фильтры по товару (`level`, dependentLOV, lovFilterAttr) требуют контекста товара и здесь не применяются.

Повторное обновление только PIM-примеров из БД kuppersberg (транзакция READ ONLY; без AI и записей в канал):

```powershell
node -r ts-node/register/transpile-only scripts/ai-mapping/refresh-review-values.cjs
```

Из `server`, без загрузки `.env` и без подключения к БД:

```powershell
node -r ts-node/register/transpile-only scripts/ai-mapping/retrieval-experiment.cjs --prepare --out docs/ai-mapping/embeddings-review-dataset.json
node -r ts-node/register/transpile-only scripts/ai-mapping/retrieval-experiment.cjs --dataset docs/ai-mapping/embeddings-review-dataset.json --cache "$env:TEMP\openpim-bge-m3-retrieval-20261012.json" --out docs/ai-mapping/embeddings-diagnostic-warm.json
node scripts/ai-mapping/retrieval-review-page.cjs docs/ai-mapping/embeddings-diagnostic-warm.json docs/ai-mapping/embeddings-review.html
```

Модель/origin можно задать через `--model`, `--base-url` либо `OPENPIM_AI_EMBEDDING_MODEL`, `OPENPIM_AI_EMBEDDING_BASE_URL`. Timeout и batch: `OPENPIM_AI_EMBEDDING_TIMEOUT_MS`, `OPENPIM_AI_EMBEDDING_BATCH_SIZE`. Настройки относятся только к CLI-эксперименту; production resolver не читает их.

Для полного снимка: `--prepare --snapshot full-snapshot.json --out full-dataset.json`. Schema снимка: `tenantId`, `language`, `groups` в формате PIM, `categories:[{id,name,attributes,valid,visibility}]`; `visibility:{paths,targetPaths,relationId}` соответствует действующему фильтру. Опционально `labels:{"categoryId/attributeId":{status:"confirmed",expectedAttrIdents:["source"],reviewer:"name",notes:""}}`. Категории должны описывать разрешённые типы/видимость; CLI не проверяет права в БД и не экспортирует данные автоматически. Переносите ручные метки только между одинаковыми каталогом, областью выбора и характеристикой.

Эталон dataset: `label.status=pending|confirmed`, `expectedAttrIdents` — массив допустимых источников, пустой массив для подтверждённого отсутствия, обязательный `reviewer` для confirmed, `notes`. Pending исключены из метрик. Отчёт содержит ranked identifiers, время, provenance/cache и incomplete flags.
