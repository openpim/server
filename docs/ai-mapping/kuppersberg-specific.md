# Специфические характеристики популярных категорий Kuppersberg

Дата: 2026-10-08. Статус: реальный эксперимент завершён; изменения алгоритма приложения на этом этапе не вносились.

После [исправления видимости и поиска](target-visibility-and-search.md) расширили проверку с часто встречающихся служебных полей на характеристики самой техники. Канал `ym`, кандидаты только из «Основные (из 1С)», модель Ollama Cloud / deepseek-v4.1-flash.

## Выборка

Те же популярные категории: варочные панели (173 товара), встраиваемые вытяжки (109), духовые шкафы (85). В каждой выбрано по 15 новых актуальных характеристик без выражений, удалённых строк и дубликатов. Все 30 строк предыдущего теста исключены.

API Яндекса не пометил ни одну актуальную характеристику этих категорий как обязательную. Поэтому данный этап проверяет специфические характеристики, а не обязательность заполнения. Скрипт поддерживает приоритет обязательных полей при их наличии.

Остальная выборка распределяется по темам по кругу, чтобы многочисленные разновидности конфорок не вытесняли материал, мощность и управление:

- Варочные панели: конфорки и их диаметры, материал поверхности, мощность, установка, управление, таймер.
- Вытяжки: производительность, мощность, скорости, режимы, шум, управление, двигатели, фильтр, освещение, встраивание.
- Духовки: тип, объём, мощность, энергопотребление, программы, гриль, очистка, температура, дверца и стёкла, конвекция.

Категория варочных панелей может включать газовые, электрические и комбинированные изделия. Наличие тематического кандидата не делает любой общий атрибут подходящим для отдельного подтипа.

## Методика и результаты

Два прогона с одинаковыми запросами для каждой категории: всего 45 новых строк и 90 результатов. Применяются целевая видимость, нормализация названий, явные типы и ограниченные примеры справочников. Существующие соответствия не передаются модели.

| Категория | Пул атрибутов 1С | Предложений, прогон 1 / 2 | Повторились ответы | Повторились непустые пары | Время, прогон 1 / 2 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Варочные панели | 135 | 4 / 5 | 12/15 | 3 | 58,1 / 44,6 с |
| Вытяжки встраиваемые | 75 | 11 / 12 | 12/15 | 10 | 72,6 / 49,7 с |
| Духовые шкафы | 127 | 11 / 10 | 14/15 | 10 | 19,1 / 21,8 с |

Всего 26 и 27 предложений в двух прогонах. Повторились 38/45 ответов: 23 непустые пары и 15 отказов. Все непустые предложения требуют проверки. Эти числа не являются точностью; вручную подтверждённый эталон не сформирован.

Загружены примеры шести, девяти и семи справочников маркетплейса соответственно. Все 45 исходных ссылок на PIM-атрибуты находятся вне shortlist группы 1С; совпадение ID с прежним маппингом не подходит для измерения качества этой выборки.

## Полезные результаты

По метаданным получены пары, которые подходят для дальнейшей проверки: максимальная производительность вытяжки, количество скоростей, объём духовки, максимальная температура, мощность СВЧ. Для мощности панели, режимов работы, очистки и типов техники также есть предложения, но им нужна проверка смысла или домена значений.

Отказы могут быть правильными: управление со смартфона не равнозначно типу управления; тип дверцы не равнозначен признаку съёмной дверцы; отдельный режим гриля не определяет тип гриля. Отказ относится к переданным кандидатам, а не доказывает отсутствие поля во всей базе.

## Выявленные ограничения

### Подмена измеряемого свойства

**Газовые конфорки → общее количество конфорок.** Первый прогон отказался, второй предложил `attr_KolichestvoKonforok`, назвав пару точной. Для комбинированной панели общее число и число газовых конфорок различаются. Без подтверждения области применения это спорное соответствие.

**Ширина встраивания → ширина изделия.** Для вытяжки предложен `attr_SHirinaSm5`. В первом пояснении модель сама отмечает, что ширина изделия и пространства для встраивания различаются, но возвращает непустую пару. Совпадение типа и сантиметров не подтверждает совпадение свойства.

Оба случая показывают, что `needsReview=true` — только сигнал проверки, а не гарантия допустимости предложения. Увеличение числа предложений само по себе не является улучшением качества.

### Преобразования единиц и представления

**Мощность гриля:** кандидат `attr_Moschnost_PodklyucheniyaGril_KVt` описан в кВт, характеристика маркетплейса — в Вт. Даже после подтверждения одинакового смысла потребуется пересчёт кВт × 1000; простой выбор атрибута этого не делает. Выражение автоматически не создавалось.

**Количество стёкол:** метаданные маркетплейса содержат справочник «одно/два/три/четыре», PIM-кандидат `attr_KolichestvoStekolDvertsi` имеет числовой type=4. Нужна таблица преобразования числа в словарное значение маркетплейса. Пояснение первого ответа модели перепутало стороны типов: утверждало, что справочник находится в PIM. Фактические типы следует проверять по метаданным, а не по тексту объяснения.

**Конвекция и мощность двигателя:** кандидаты используют словарь при булевой или числовой характеристике маркетплейса. Возможность преобразования зависит от действительного домена значений. Общий LOV у 901 атрибута не подтверждает этот домен.

### Неоднозначные области и названия

В двух прогонах меняются решения по типу варочной поверхности, номинальной мощности, типу управления и встраивания вытяжки, дистанционному управлению и мощности подключения духовки. Для дистанционного управления набор вариантов маркетплейса может включать пульт, жесты и смартфон; поле «Пульт ДУ» описывает лишь часть этого набора.

Поля с одинаковыми или близкими названиями требуют описания назначения и области применения. Синонимы помогают найти кандидата, но не устанавливают эквивалентность характеристик.

## Следующие шаги

1. Сформировать проверяемые примеры для различения свойства изделия и его части/подтипа: газовые против всех конфорок, размеры изделия против встраивания. Добавить сведения о назначении поля там, где их нет.
2. Разделить в предложениях прямое соответствие, соответствие с преобразованием и неоднозначный выбор. Для преобразований нужна отдельная спецификация; атрибут без правила не обеспечивает корректную выгрузку.
3. Проверять типы и явные единицы по серверным метаданным. Пояснение LLM не должно быть источником этих фактов.
4. Сохранять память соответствий после подтверждения; не превращать повторившиеся предложения в подтверждённые автоматически.

БД, код приложения, настройки модели и интерфейс на этом этапе не менялись. Преобразования и память подтверждений пока не реализованы. Синтаксис операторских скриптов и `git diff --check` проверены; целевые тесты приложения из предыдущего этапа не перезапускались.
