# Варианты справочников в контексте AI-маппинга

Дата: 2026-10-08. Ветка `server/AIMappingAssistant`.

Пользователь уточнил: передавать варианты нейронке для выбора соответствий атрибутов. Обогащение подключено к `suggestChannelAttributeMappings`; оно действует для общей кнопки и кнопки одной строки. GraphQL-ответ и интерфейс применения не изменены.

## Что получает модель

Помимо названий, описаний и групп, модель получает:

- `typeName` PIM-кандидата и `numeric`: 3 — integer, 4 — float, 7 — dictionary. Системный prompt также содержит полную расшифровку типов 1–9.
- `valueOptions` для доступных словарных характеристик обеих сторон: статус, до восьми уникальных локализованных примеров, число записей при известном полном размере и признак усечения.
- `sharedByAttributes` PIM-справочника: число уникальных атрибутов в загруженном наборе групп, указывающих на этот LOV, включая несловарные поля с оставшейся ссылкой. Это происхождение контекста, а не оценка уверенности.
- `unit` маркетплейса, если обработчик предоставил явную единицу. Яндекс передаёт имя defaultUnit. Единицы PIM продолжают учитываться по доступным названиям; универсальный источник единиц PIM не добавлен.

Примеры — только подписи значений, до 80 символов каждая. ID значений, URL словаря, заголовки запросов и конфигурация канала в контекст не попадают. Значения конкретных товаров не читаются.

`loaded` с пустым списком означает успешно полученный пустой словарь. `unavailable` означает отсутствие контекста, ошибку, неподдерживаемый источник или превышение лимитов. Неполная выборка не доказывает, что отсутствующего в ней варианта нет в справочнике.

## Источники и ограничения

PIM: загружаются только LOV словарных кандидатов после отбора top-30. Запрос связан с tenant, исключает удалённые LOV и возвращает первые восемь элементов плюс полный размер. Прямое индексирование JSON-массива не разворачивает весь большой справочник. До 200 уникальных LOV на операцию; остальные отмечаются как недоступные. Словарность определяется типом 7: старая ссылка `lov` у Float не превращает число в словарь.

Яндекс Маркет: варианты `param.values` берутся из уже полученного ответа категории. Дополнительный запрос не нужен, если значения присутствуют. Если вариантов нет в метаданных, ограниченный загрузчик может получить их из известного endpoint категории.

Ozon: используется первая страница существующего endpoint значений атрибута. Загрузчик разрешает только два известных URL Ozon и URL параметров категории Яндекса, передаёт явно выбранные поля тела/заголовков. Redirect запрещён, ответ ограничен 512 KiB, один вызов — максимум 5 с, суммарное окно marketplace-загрузок — 10 с, максимум 20 внешних lookup на операцию. Полная пагинация не выполняется.

WB: текущий обработчик не предоставляет словари этих характеристик. Там применимы доступные словари PIM; отсутствующие варианты маркетплейса не выдумываются. Реальная проверка Ozon/WB в этом этапе не выполнялась.

Настроенный `batchSize` теперь верхняя граница: большой пакет автоматически уменьшается целыми строками до примерно 190000 символов полезной нагрузки. Лимит провайдера 200000 сохраняется; общий timeout по-прежнему действует на всю последовательность LLM-пакетов. Обогащение словарями происходит до этого отсчёта; marketplace-загрузка ограничена отдельно. Новые `.env` параметры не нужны.

## Реальная проверка Kuppersberg

READ ONLY прогон пяти характеристик винных шкафов, кандидаты только из «Основные (из 1С)». Проверены температурные зоны, энергокласс, управление, компрессор и материал полок. Обе стороны получили варианты; база и маппинги не менялись.

Первый контекстный прогон занял 13,232 с и дал пять предложений. Он обнаружил, что связанные PIM-справочники возвращают одинаковые разнородные примеры: «177х900х300», «KFP 2 (приобретается отдельно)» и другие. Проверка атрибутов подтвердила: LOV id 3 прикреплён к 901 атрибуту основной группы, в том числе числовым.

После этого исправлены словарность несловарных полей и происхождение shared-контекста. Второй прогон занял 7,258 с, дал четыре предложения и один отказ; все предложения требуют проверки. Загружены все пять marketplace-справочников; 118 вхождений PIM-кандидатов в пяти shortlist получили примеры общего LOV — это число вхождений, а не 118 уникальных справочников.

| Характеристика | Примеры маркетплейса | Итог после исправлений |
| --- | --- | --- |
| Температурные зоны | монотемпературный, двухтемпературный, трехтемпературный | `attr_KolVoTemperaturnihZon`; модель распознала Float и необходимость преобразования числа в словарь |
| Энергокласс | A, A+, A++, A+++, B… | отказ: несколько одинаковых атрибутов с общим LOV и нерелевантными примерами |
| Управление | электромеханическое, электронное | `attr_TipUpravleniya2`; общий LOV не подтверждает домен значений |
| Компрессор | инверторный, стандартный | `attr_TipKompressora`; общий LOV не подтверждает домен значений |
| Материал полок | дерево, металл, пластик, стекло | `attr_MaterialPolok`; общий LOV не подтверждает домен значений |

В первом ответе модель сочла материал полок совместимым, хотя примеры PIM были нерелевантны. После явной отметки shared-контекста она указывает, что совместимость домена не подтверждена. Это подтверждает необходимость происхождения данных и проверки, а не измеряет точность модели.

Чистого A/B теста пользы справочников нет: одновременно добавлены типы, инструкции о значениях, затем исправлена словарность; состав пакета отличается от прежнего полного прогона категории. Отбор по именам и проблема видимости обычных атрибутов 1С в этом этапе не исправлены. Значения добавляются после shortlist и не возвращают потерянный до него кандидат «Цвет».

## Проверки и артефакты

Прошли 43 серверных теста и TypeScript-проверка. Новые проверки покрывают локализацию, усечение, исключение лишних полей, общий LOV, неправильные ссылки у Float, tenant-изоляцию SQL, передачу через resolver, разрешённые endpoint, остановку зависшего тела ответа и размер LLM-пакетов.

- [Итоговый прогон с shared-контекстом](kuppersberg-values-evaluation.json).

- `src/channels/ai/access.ts`: подключение к запросу AI.

Чтобы пользоваться обновлением, перезапустить сервер. Новой сборки `web3` для этого изменения не требуется.

Следующий приоритет — исправить видимость и нормализацию shortlist, затем определить допустимые значения конкретного атрибута внутри общего LOV. Обычная передача первых вариантов общего справочника не решает эту задачу. Автоматическое создание соответствий между значениями словарей не реализовано.
