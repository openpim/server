## Когда запускается AIMapping

Механизм запускается при запросе AI-подбора через `suggestChannelAttributeMappings`. Открытие редактора, ручной выбор PIM-атрибута и обычный экспорт канала сами по себе embeddings не запускают.

Условия работы:

- `OPENPIM_AI_MAPPING_ENABLED=true` и корректно настроен финальный LLM;
- поддерживаемый канал: Wildberries (тип 2), Ozon (тип 3), Yandex Market (тип 9);
- пользователь авторизован, имеет доступ к просмотру/редактированию канала и редактированию конфигурации каналов;
- запрошены существующие характеристики маркетплейса и настроенный язык;
- для embeddings выбран `hybrid`, доступна локальная Ollama с установленной embedding-моделью.

Режимы:

| Режим | Как отбираются кандидаты | Нужна Ollama | Нужен финальный LLM |
| --- | --- | --- | --- |
| `hybrid` | Текстовое ранжирование + семантическое сравнение профилей, затем RRF | Да; при сбое срабатывает fallback | Да |
| `lexical` | Прежнее текстовое ранжирование | Нет | Да |
| AIMapping выключен | AI-подбор недоступен | Нет | Нет |

`lexical` отключает только embeddings. Чтобы полностью отключить AI-подбор, установите `OPENPIM_AI_MAPPING_ENABLED=false`.

## Данные и порядок

С 16 октября 2026 года UI поддерживает выбор нескольких групп с поиском, галочками и удаляемыми метками. Пустой выбор означает все доступные группы. Перед top-30 сервер объединяет атрибуты выбранных групп и убирает дубликаты; отдельного LLM-запроса на каждую группу нет. Выбор хранится в текущем компоненте, а не в конфигурации канала.

GraphQL-аргумент `groupIdentifiers: [String!]` принимает до 200 identifiers, каждый непустой и не длиннее 250 символов. Скрытые, неизвестные или неоднозначные группы отклоняются. Прежний одиночный `groupIdentifier` сохранён для старых клиентов; одновременно передавать оба ограничения нельзя. Для нового UI сначала обновите backend: старая GraphQL-схема plural-аргумент не принимает.

1. Сервер строит полный разрешённый пул с прежними фильтрами групп, типов и category visibility.
2. До отбора top-30 загружает ограниченные примеры справочников PIM и маркетплейса существующими loaders, в том числе с фильтром LOV по PIM-атрибуту.
3. Смысловой профиль: название, описание, группа/категория, тип, явная единица измерения. Описание PIM берётся из `description` или опции `description`, локализуется и ограничивается 1500 символами. Единица PIM используется при наличии явного поля, автоматически из названия не извлекается. Профиль ограничен 6000 символами. Идентификаторы PIM остаются сигналом текстового поиска; ключи API и произвольные options не включаются.
4. Значения образуют отдельный профиль (до восьми строк, до 80 символов). Семантический балл: `0.85 * cosine(meaning) + 0.15 * cosine(values)`; при отсутствии информативных значений с любой стороны добавочный балл равен нулю. Веса — исходная эвристика, не откалиброванная на эталонах.
5. «Да/Нет», true/false, 0/1 и общие отсутствующие значения не участвуют в семантическом сравнении значений. Неотфильтрованные справочники, переиспользуемые несколькими атрибутами, также не участвуют. Примеры остаются доступны финальному LLM с прежними отметками ограниченности.
6. Существующий RRF объединяет текстовый и семантический порядок с сохранением точных совпадений названия, затем берётся top-30. Это кандидаты для LLM, не подтверждение соответствия.

Фактические значения товаров обычных текстовых/числовых полей здесь не запрашиваются. Используются описания текущих channel handlers, без новых endpoints маркетплейса. Выборки ограничены прежними loaders: до 200 LOV, до 20 дополнительных запросов справочников маркетплейса и общий бюджет этих marketplace lookups 10 секунд. Остальные данные имеют статус unavailable; отсутствие примера не считается несовместимостью.

## Настройка

При `OPENPIM_AI_MAPPING_ENABLED=true` режим по умолчанию — `hybrid`. Отключение семантического поиска: `OPENPIM_AI_MAPPING_RETRIEVAL=lexical`. Старые программно созданные конфигурации без `retrievalMode` сохраняют текстовый режим.

### Где хранятся настройки

При обычном локальном запуске добавьте параметры в `server/.env`, сохранив остальные настройки приложения и БД. Сервер вызывает `dotenv.config()` в `src/index.ts`; файл ищется относительно рабочего каталога процесса. Запускайте сервер из каталога `server`.

Значения можно передать и через окружение процесса, службу запуска или контейнер. Уже заданные переменные окружения по стандартному поведению используемого вызова dotenv не перезаписываются `.env`: если изменение файла не действует, проверьте окружение службы/контейнера.

После изменения настроек перезапустите процесс сервера. Текущий `nodemon.json` следит за `src`, а `.env` в его список наблюдения не входит. Сам файл `.env` эта доработка не заполняет.

### Если AI-подбор уже работал

Существующие параметры финального LLM оставьте. Добавьте или обновите только этот блок, без повторного объявления той же переменной в другом месте файла:

```dotenv
OPENPIM_AI_MAPPING_RETRIEVAL=hybrid
OPENPIM_AI_EMBEDDING_BASE_URL=http://127.0.0.1:11434
OPENPIM_AI_EMBEDDING_MODEL=bge-m3:latest
OPENPIM_AI_EMBEDDING_BATCH_SIZE=16
OPENPIM_AI_EMBEDDING_TIMEOUT_MS=60000
```

Даже без этого блока embeddings используют указанные значения по умолчанию. Однако это работает только при включённом AIMapping и доступной локальной модели.

### Полный блок конфигурации

Ниже шаблон для OpenAI-compatible провайдера финального LLM. Замените URL, ключ и имя chat-модели значениями вашего провайдера. Пустые обязательные поля намеренно оставлены для заполнения: без них шаблон не является готовой рабочей конфигурацией.

```dotenv
# Включение AI-подбора
OPENPIM_AI_MAPPING_ENABLED=true
OPENPIM_AI_MAPPING_RETRIEVAL=hybrid

# Финальный LLM: заполнить URL, ключ при необходимости и имя chat-модели
OPENPIM_AI_PROVIDER=openai-compatible
OPENPIM_AI_BASE_URL=
OPENPIM_AI_API_KEY=
OPENPIM_AI_MODEL=
OPENPIM_AI_RESPONSE_FORMAT=json_object
OPENPIM_AI_TIMEOUT_MS=60000
OPENPIM_AI_MAPPING_BATCH_SIZE=20
OPENPIM_AI_USE_SYSTEM_CA=false

# Локальная embedding-модель
OPENPIM_AI_EMBEDDING_BASE_URL=http://127.0.0.1:11434
OPENPIM_AI_EMBEDDING_MODEL=bge-m3:latest
OPENPIM_AI_EMBEDDING_BATCH_SIZE=16
OPENPIM_AI_EMBEDDING_TIMEOUT_MS=60000
```

Готовый файл-шаблон для копирования отдельных настроек: [ai-mapping.env.example](../channels/ai-mapping.env.example). Не заменяйте им целиком рабочий `.env`: там находятся и другие настройки сервера. Реальные ключи не добавляйте в документацию или Git.

### Параметры финального LLM и общего режима

| Переменная | По умолчанию | Допустимые значения и назначение |
| --- | --- | --- |
| `OPENPIM_AI_MAPPING_ENABLED` | Выключено | Включается только точной строкой `true` |
| `OPENPIM_AI_MAPPING_RETRIEVAL` | `hybrid` | `hybrid` или `lexical`; читается при включённом AIMapping |
| `OPENPIM_AI_PROVIDER` | `openai` | `openai` или `openai-compatible` |
| `OPENPIM_AI_BASE_URL` | `https://api.openai.com/v1` для `openai` | Для `openai-compatible` обязателен URL. Сервер добавляет `/chat/completions`, поэтому полный путь до этого endpoint указывать не нужно |
| `OPENPIM_AI_API_KEY` | Пусто | Обязателен для `openai`; для `openai-compatible` зависит от сервиса |
| `OPENPIM_AI_MODEL` | Нет | Обязательное имя модели финального LLM; это не имя embedding-модели |
| `OPENPIM_AI_RESPONSE_FORMAT` | `json_schema` | `json_schema` для строгой schema либо `json_object`, если провайдер поддерживает только JSON object |
| `OPENPIM_AI_TIMEOUT_MS` | `60000` | Целое 1–300000 ms. Общий бюджет всех batches финального LLM одного подбора |
| `OPENPIM_AI_MAPPING_BATCH_SIZE` | `20` | Целое 1–30 характеристик на batch финального LLM; при большом payload batch автоматически уменьшается |
| `OPENPIM_AI_USE_SYSTEM_CA` | `false` | Только `true` включает системные CA для HTTPS-запросов final LLM и marketplace dictionary loader; требуется Node.js с `tls.getCACertificates`. Проверка сертификатов остаётся включена |

URL провайдера не должен содержать логин/пароль, query или fragment. Для удалённого endpoint с ключом требуется HTTPS; HTTP с ключом допускается только для loopback. Поддержка выбранного JSON-формата зависит от финального LLM-провайдера.

### Параметры embeddings

| Переменная | По умолчанию | Допустимые значения и назначение |
| --- | --- | --- |
| `OPENPIM_AI_EMBEDDING_BASE_URL` | `http://127.0.0.1:11434` | Только HTTP loopback origin: `127.0.0.1`, `localhost`, `[::1]`. Без URL credentials, query, fragment или дополнительного пути |
| `OPENPIM_AI_EMBEDDING_MODEL` | `bge-m3:latest` | Имя уже установленной локальной embedding-модели. Если tag не указан, добавляется `:latest`. Cloud-модели запрещены |
| `OPENPIM_AI_EMBEDDING_BATCH_SIZE` | `16` | Целое 1–32 текста за HTTP-запрос к Ollama, не число характеристик маркетплейса |
| `OPENPIM_AI_EMBEDDING_TIMEOUT_MS` | `60000` | Целое 1–300000 ms на один HTTP-запрос; дополнительно действует общий runtime-бюджет 60000 ms |

Для embedding timeout и batch параметр нужно либо не задавать, либо заполнить корректным числом: пустое значение не равнозначно отсутствующему и считается ошибкой. Эти ошибки в hybrid приводят к fallback.

Для runtime-поиска веса `0.85/0.15`, RRF `k=60`, top-30, предел 2000 кандидатов, общий бюджет 60 секунд, размер/время жизни кэша и `keep_alive:2m` заданы в коде. Отдельных `.env`-переменных для них нет. Увеличение HTTP timeout до 120000 не увеличит общий бюджет поиска.

### Быстрое отключение

Вернуться к текстовому отбору с сохранением финального LLM:

```dotenv
OPENPIM_AI_MAPPING_RETRIEVAL=lexical
```

Выключить AI-подбор полностью:

```dotenv
OPENPIM_AI_MAPPING_ENABLED=false
```

В обоих случаях перезапустите сервер.

## Подготовка Ollama и запуск

Команды ниже выполняются оператором. Приложение само Ollama не устанавливает и модель не скачивает.

1. Установите и запустите Ollama на машине/в сетевой области, где работает backend. Используйте [официальный сайт Ollama](https://ollama.com/download).
2. Проверьте локальные модели:

   ```powershell
   ollama ls
   ```

3. Если `bge-m3` отсутствует, скачайте её явно:

   ```powershell
   ollama pull bge-m3
   ```

4. Если Ollama не запущена как приложение или служба, запустите её в отдельном терминале:

   ```powershell
   ollama serve
   ```

   Если сервис уже слушает порт 11434, второй экземпляр запускать не нужно. Команды описаны в [Ollama CLI Reference](https://docs.ollama.com/cli), модель — в [каталоге BGE-M3](https://ollama.com/library/bge-m3).

5. Из той же сетевой области, где будет backend, проверьте список моделей по HTTP:

   ```powershell
   $ollamaModels = Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/tags' -TimeoutSec 10
   $ollamaModels.models | Select-Object name, digest
   ```

   Ответ должен содержать настроенную модель. Описание API: [List models](https://docs.ollama.com/api/tags). Доступность этого endpoint ещё не доказывает способность модели строить embeddings.

6. Проверьте локальный вызов embedding API:

   ```powershell
   $embeddingBody = @{
       model = 'bge-m3:latest'
       input = @('Материал рабочей поверхности', 'Покрытие варочной панели')
       truncate = $false
   } | ConvertTo-Json
   $embeddingResult = Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/embed' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($embeddingBody)) -TimeoutSec 60
   $embeddingResult.embeddings.Count
   $embeddingResult.embeddings[0].Count
   ```

   Первая команда вывода должна показать два вектора; вторая — их размерность. Эти данные синтетические, backend и БД здесь не используются.

7. Настройте `.env`, затем запустите или перезапустите backend своим обычным способом. Для локальной разработки из каталога `server`:

   ```powershell
   npm run dev
   ```

8. Выполните AI-подбор в интерфейсе и проверьте `review.retrieval` по инструкции ниже. Успех отдельного embedding API-вызова не подтверждает работу финального LLM.

## Docker и удалённые серверы

`127.0.0.1` относится к среде, в которой выполняется процесс OpenPIM:

| Размещение | Что требуется |
| --- | --- |
| Backend и Ollama запущены напрямую на одной машине | Обычный loopback URL `http://127.0.0.1:11434` |
| Backend на другом сервере | Ollama должна быть доступна через loopback именно на том сервере; Ollama на компьютере пользователя не используется автоматически |
| Backend в Docker, Ollama на хосте | Loopback контейнера не является хостом. Нужна настроенная сетевая схема с loopback-доступом из backend; одной замены URL недостаточно |
| Backend и Ollama в отдельных контейнерах | Обычное имя сервиса вроде `http://ollama:11434` текущий клиент отклоняет. Нужна общая сетевая область с loopback или отдельная доработка клиента |

`host.docker.internal`, IP локальной сети и удалённые HTTP/HTTPS origins текущая реализация embeddings не принимает. Не указывайте их как готовое решение: получится текстовый fallback.

В текущем `docker/Dockerfile` файл `docker/server_env` копируется в `/server/.env` при сборке. Изменение `server/.env` на хосте само по себе уже созданный контейнер не обновляет. Для контейнера передавайте настройки через принятую схему окружения/`env_file` и пересоздавайте его либо обновляйте образ по вашей процедуре.

Dockerfile сейчас основан на `node:16`, тогда как возможность системных CA проверяется через `tls.getCACertificates`. Если включаете `OPENPIM_AI_USE_SYSTEM_CA=true`, заранее проверьте Node.js фактического процесса; сам флаг не обновляет runtime. Эта документация не меняет контейнеризацию и версии Node.js.

Контракт `/api/embed` проверен по [официальной документации Ollama](https://docs.ollama.com/api/embed): batch input, `truncate:false`, `keep_alive`, проверка модели и векторов ответа.

## Ограничения и диагностика

- Для пула более 2000 разрешённых атрибутов используется текстовый top-30 без полного обогащения. Область можно сузить существующим выбором группы.
- Общий deadline поиска — 60 секунд, включая обнаружение модели, все batches, чтение body и ранжирование. Нормализация векторов выполняется один раз; между характеристиками сервер передаёт управление другим запросам. Настройка timeout может уменьшить время отдельного HTTP-запроса. Это отдельный бюджет от metadata и финального LLM.
- Сбой, timeout, неверные векторы или недоступная модель приводят к текстовому fallback. Сырые ошибки и тела ответов не возвращаются пользователю.
- `review.retrieval`: `mode`, число разрешённых кандидатов, `elapsedMs` и при fallback код `embedding_unavailable` или `pool_limit`. Отдельное отображение диагностики в UI не добавлялось.
- Один процессный LRU-кэш: до 30 MiB в компактном JSON-представлении / 20 000 записей. Объекты JavaScript требуют дополнительной памяти. Ключ разделён по tenant/channel, языку, модели/digest и тексту профиля. Изменение описания/значений создаёт новый ключ. Клиент пересоздаётся раз в пять минут для повторной проверки модели; при этом кэш сбрасывается. Перезапуск процесса также сбрасывает кэш.

### Дополнительные пределы

| Ограничение | Значение |
| --- | --- |
| Характеристик маркетплейса в одном запросе | 1–200 |
| Одновременно выполняющихся AI-подборов одного tenant в одном процессе | 1; второй получает ошибку занятости |
| Кандидатов на одну характеристику для финального LLM | До 30 |
| Уникальных текстов за вызов embedding-клиента | До 10000 |
| Размерность одного вектора | 1–4096 |
| Общее число компонентов векторов результата одного вызова | До `4 * 1024 * 1024` |
| Размер HTTP-ответа Ollama | До 8 MiB |
| Примеры значений | До 8, каждый до 80 символов |
| Длина описания маркетплейса и PIM в mapping metadata | До 1500 символов |

Слишком большие или некорректные embedding-ответы приводят к fallback. Ограничения tenant lock и кэша относятся к одному серверному процессу: между репликами общего runtime-кэша и распределённой блокировки здесь нет.

### Что сохраняется в кэше

Runtime сохраняет в памяти хэши ключей и векторы. Ключ учитывает origin Ollama, модель и её digest, scope из tenant/channel, язык и текст профиля. Категория входит в смысловой профиль запроса; группа — в профиль PIM-кандидата. Подбор всегда выполняется по текущему разрешённому пулу: кэш не расширяет права или видимость.

На диск runtime-кэш не записывается. Файловый кэш CLI-эксперимента из `local-embeddings.md` — отдельный механизм; его путь не является настройкой рабочего AIMapping. При обновлении model tag в уже работающем процессе новая проверка digest произойдёт при пересоздании клиента, максимум после его текущего пятиминутного срока жизни при следующем запросе. Для немедленной повторной проверки перезапустите backend.

### Куда отправляются данные

| Получатель | Данные |
| --- | --- |
| Локальная Ollama | Только смысловые профили и отдельные примеры справочных значений |
| Финальный LLM-провайдер | Контекст маркетплейса/категории/языка, выбранные характеристики и до 30 кандидатов с описательными метаданными и примерами |
| API маркетплейса | Ограниченные запросы нужных справочников с существующими ключами канала |

Локальные embeddings не делают финальный LLM автоматически локальным. Его размещение и стоимость определяются `OPENPIM_AI_PROVIDER`, `OPENPIM_AI_BASE_URL` и `OPENPIM_AI_MODEL`. Ключи канала и произвольные заголовки не включаются в профили/контекст модели. Описания и примеры рассматриваются как недоверенные метаданные, а не инструкции.

## Проверка фактически использованного режима

`getChannelAIMappingStatus` проверяет поддержку канала и общую конфигурацию AI-подбора. Он не вызывает Ollama и финальный LLM и не является проверкой их доступности. Поэтому `enabled:true` не гарантирует hybrid.

Откройте инструменты разработчика браузера → Network, выполните подбор и найдите ответ GraphQL-операции `suggestChannelAttributeMappings`. В объекте результата посмотрите `review.retrieval`. В существующем JSON review диагностика доступна без изменения GraphQL-схемы, однако отдельного индикатора режима в UI пока нет. Если ваш собственный GraphQL-клиент не запрашивает поле `review`, добавьте его в selection set.

Пример успешного гибридного поиска (числа иллюстративные):

```json
{
  "review": {
    "retrieval": {
      "mode": "hybrid",
      "candidates": 285,
      "elapsedMs": 540
    }
  }
}
```

Пример fallback:

```json
{
  "review": {
    "retrieval": {
      "mode": "lexical",
      "fallback": "embedding_unavailable",
      "candidates": 285,
      "elapsedMs": 60002
    }
  }
}
```

| Поле/значение | Как трактовать |
| --- | --- |
| `mode: hybrid` | Семантическое и текстовое ранжирование выполнены, финальный LLM получил гибридный shortlist |
| `mode: lexical`, без `fallback` | Явный текстовый режим, legacy config без retrievalMode либо пустой разрешённый пул |
| `fallback: embedding_unavailable` | Ошибка конфигурации embedding-клиента, недоступность/timeout, неподходящая модель, неверные векторы, лимит ответа/памяти или исчерпанный общий бюджет |
| `fallback: pool_limit` | Полный разрешённый пул превышает 2000 кандидатов |
| `candidates` | Размер разрешённого пула до top-30, не количество предложенных соответствий |
| `elapsedMs` | Время этапа поиска; без предшествующего обогащения справочников и последующего финального LLM |

Код fallback намеренно общий: сырой ответ провайдера или текст исключения не выдаётся в review. Диагностика появляется в возвращённых предложениях; если сам запрос завершился ошибкой до результата либо предложений нет, отдельного объекта retrieval в ответе может не быть.

## Типовые проблемы

| Симптом | Что проверить и сделать |
| --- | --- |
| В `.env` нет embedding-параметров | Используются defaults. Добавьте явный блок из раздела настройки, если нужно сделать конфигурацию видимой |
| AI-подбор выключен | Установите точную строку `OPENPIM_AI_MAPPING_ENABLED=true`, заполните модель/URL/ключ финального LLM и перезапустите backend |
| `OPENPIM_AI_MODEL is required` | Это имя chat-модели финального LLM; `OPENPIM_AI_EMBEDDING_MODEL` его не заменяет |
| После изменения `.env` поведение прежнее | Проверьте рабочий каталог процесса, его окружение, путь конфигурации службы/контейнера и факт перезапуска |
| В review `embedding_unavailable` | Из среды backend проверьте `/api/tags`, затем `/api/embed`; убедитесь в наличии точного model tag и embedding capability. Проверьте числовые настройки, loopback URL и общий бюджет |
| Ollama работает на хосте, backend в Docker всё равно делает fallback | `127.0.0.1` контейнера относится к контейнеру. Проверьте сетевую схему; `host.docker.internal` и имя соседнего сервиса клиент не принимает |
| В review `pool_limit` | Выберите подходящую группу PIM, уменьшая разрешённый пул. Увеличением HTTP timeout это не исправить |
| Первая попытка медленная | В cold-start загружается модель и строятся новые векторы. Повтор может использовать кэш, если профили/область не изменились и клиент не пересоздан |
| Кэш иногда перестраивается | Он процессный, ограниченный, сбрасывается при перезапуске и пересоздании клиента; записи вытесняются по LRU |
| В примерах нет ожидаемого значения | Это ограниченная выборка, не весь справочник. Учитывайте `truncated`, `total`, `unavailable` и переиспользование LOV |
| Найден похожий, но неверный атрибут | Сверьте объект измерения, описание, единицы, группу и значения; оставьте без соответствия или выберите вручную. Семантическая близость не доказывает совпадение свойства |
| Ошибка занятости tenant | Дождитесь завершения предыдущего подбора. Параллельные запросы одного tenant в одном процессе отклоняются |
| Провайдер отклоняет structured output | Выберите поддерживаемый `OPENPIM_AI_RESPONSE_FORMAT`; для сервисов без JSON Schema предусмотрен `json_object` |
| Ошибка системных CA | Проверьте поддержку `tls.getCACertificates` вашим Node.js. Флаг не отключает проверку TLS и не исправляет несовместимый runtime |

## Проверка

Из `server`:

```powershell
node -r ts-node/register/transpile-only --test tests/ai-mapping*.test.cjs tests/aimapping*.test.cjs
node node_modules/typescript/bin/tsc --noEmit -p .
node -r ts-node/register/transpile-only scripts/ai-mapping/runtime-smoke.cjs
```

Последняя команда использует синтетические атрибуты и локальную модель, без `.env`, БД и финального LLM. Измеренный smoke 15 октября: 7 уникальных текстов, один embedding-запрос, 17 031 ms первый проход, 2 ms повторный, 7 попаданий в кэш без новых embedding-запросов. Это проверка транспорта и кэша, не точности или полного каталога. Синтетический пример вернул порядок `packaging, surface, control`: RRF может оставлять неоднозначность, которую должен разбирать финальный LLM.

Для утверждения об улучшении качества нужны подтверждённые человеком соответствия, полные пулы и сравнение Recall@30/MRR@30, затем отдельная оценка решений LLM. Отдельный reranker не добавлялся.

Финальная проверка текущего изменения: 95/95 тестов AIMapping, TypeScript noEmit и `git diff --check`. Независимый review нашёл блокировку event loop на больших выборках; после исправления и добавления регрессий новых actionable замечаний не осталось. Синтетический batch 200 × 2000 × 1024 на повторном review: 1357 ms всего, таймер другого запроса сработал через 104 ms до завершения обработки. Это измерение на конкретном стенде, не гарантия latency.

Smoke-команда не загружает `.env`: она получает настройки из окружения процесса или defaults embedding-клиента. Если в `.env` указан нестандартный порт/модель, задайте соответствующие переменные в окружении терминала перед запуском smoke. Успешный smoke подтверждает локальный транспорт и повторное использование кэша, но не настройки финального LLM и не сквозную работу с реальным каналом.

## Приёмка на реальном каталоге

Технические тесты подтверждают реализацию, а не улучшение качества. Для сравнения со старым алгоритмом используйте одинаковые снимок метаданных, категорию, язык, видимость и группу PIM.

1. Подготовьте набор вручную проверяемых характеристик: простые соответствия, синонимы, неоднозначные названия, упаковка/изделие, разные единицы и справочники.
2. Для каждой строки задайте допустимые источники либо подтверждённое отсутствие соответствия. Старые маппинги и ответы LLM автоматически эталоном не считаются.
3. Сравните `lexical` и `hybrid` на одинаковом полном разрешённом пуле. Для практического UI-прогона переключайте режим с перезапуском backend; проверяйте фактический `review.retrieval.mode`.
4. Для ранжирования оцените Recall@30 и MRR@30 по полным пулам и подтверждённым положительным меткам. Исторические объединения shortlist не являются полным пулом.
5. Отдельно проверьте решение финального LLM, случаи неверного совпадения/пропуска, необходимость преобразований и время ответа. Присутствие нужного кандидата в top-30 ещё не означает правильный итоговый выбор.
6. Проведите ручную приёмку на согласованной копии категории. Сохранение и экспорт проверяйте отдельным шагом по рабочему регламенту. Существующее соглашение о ручной приёмке перед merge/push сохраняется.

Веса смысл/значения и RRF пока фиксированы; подтверждённых оснований заявлять процент улучшения точности нет. На синтетическом smoke упаковка оказалась выше поверхности: это известный пример неоднозначности списка кандидатов, который должен разрешаться финальным LLM и человеком. Отдельная модель reranker в эту итерацию не входит.

Эксперимент и инструмент ручной разметки описаны в [local-embeddings.md](local-embeddings.md). Описание сохранения и проверок выражений: [iteration2.md](iteration2.md).
