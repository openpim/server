# Kuppersberg: тест на атрибутах из 1С

Дата: 2026-10-08. Ветка server: `AIMappingAssistant`. По уточнению пользователя кандидаты ограничены группой **Основные (из 1С)**, `mainAttrGroup`, id 6. В базе также есть отдельная группа «1C» из двух атрибутов; в тесте используется основная группа из 926 атрибутов.

## Что проверено

Две категории: «Сковороды-гриль» и «Винные шкафы». По два прогона на одинаковых данных внутри категории. До 30 актуальных характеристик без выражений/дубликатов, до 30 кандидатов на строку. Группа ограничена ДО ранжирования. Текущий AI-фильтр видимости оставляет 917 из 926 атрибутов в обеих категориях.

Провайдер `https://ollama.com/v1`, модель `deepseek-v4.1-flash`, json_object, пакет 5, бюджет 300000 мс на один прогон. Всего 106 оценок характеристик: 24×2 + 29×2. Модель получает только метаданные характеристик и кандидатов. Прежние соответствия, товарные значения и ключи маркетплейсов не отправляются.

В оригинале соответствия ведут на другую группу — атрибуты Яндекс Маркета. Их ID исключены из кандидатов 1С. Поэтому прямое совпадение с прежними ID равно нулю и **не является оценкой точности**. Полноценный семантический эталон 1С ещё не составлен; humanVerdict в отчётах pending. Пустой ответ может быть корректным отказом.

## Найденные проблемы

### 1. Модель неверно понимает код типа

Контракт `web3/src/constants/attributeTypes.js`: Text=1, Boolean=2, Integer=3, Float=4, Date=5, Time=6, LOV=7, URL=8, Relation=9. В кандидатах модели передаётся raw type, но системный prompt не объясняет значения кодов.

На первом прогоне винных шкафов модель назвала type=4 справочным типом и отказалась от числовых размеров. На втором предложила высоту/ширину/глубину. Ошибка есть и в пояснении выбора «Вес, кг». Это фактическая ошибка интерпретации локального контракта; отказ нельзя автоматически считать доказательством несовместимости. Не все отказы этим объясняются: часть атрибутов действительно type=7.

### 2. Видимость обычных атрибутов 1С почти не используется

В mainAttrGroup все 926 атрибутов имеют relations=[]. Текущий фильтр при category.visibleRelation сохраняет этот домен, чтобы не применять путь каталога к атрибутам другого домена. Поэтому отсеиваются лишь девять атрибутов, а модель видит множество характеристик чужой техники.

Дополнительная READ ONLY диагностика связей категории по visibleRelation=38 получила один связанный объект для сковород и семь для винных шкафов. Пересечение visible обычных атрибутов с предками target.path дало **34** и **65** атрибутов. Это диагностический ориентир: полный алгоритм должен учитывать valid, фактические пути объектов, стандартные поля, доступ и разные виды зависимостей; производственный фильтр в этом этапе не меняли.

Для сковород предложенный attr_VesKg «Вес, кг» не входит в диагностические 34 видимых атрибута; там есть общий attr_ves «Вес». Следовательно, даже устойчивое предложение нужно проверить на применимость к объекту, а не только по названию.

### 3. Отбор теряет существующие аналоги

В группе есть attr_TSvet9 «Цвет», он входит в диагностический набор видимости, но отсутствует в обоих shortlist цветовых характеристик. Название «Название цвета от производителя» не нормализуется к «Цвет», а общий токен «для» влияет на «Цвет для фильтра». Среди результатов появляются нерелевантные атрибуты до лимита top-30. Отказ модели означает лишь отсутствие аналога среди переданных кандидатов.

Для винных шкафов также есть «Кол-во компрессоров» и «Кол-во полок». Модель отказалась от «Количество компрессоров», а для количества полок в первом прогоне предложила идентификатор вне shortlist; сервер оставил строку пустой. Нужно проверить раскрытие сокращений и ранжирование.

### 4. В части данных может не быть предметного аналога

Поиск по названиям всех 926 атрибутов не нашёл «сковор…», «антиприг…» и «упаков…». Это свидетельство нехватки явно названных характеристик посуды в этой группе, но не доказательство отсутствия любых семантических эквивалентов. Такие случаи нужно отличать от потери существующего кандидата и от неверного отказа по типу.

Для винных шкафов доступны предметные аналоги температурных зон, управления, компрессора, климатического класса, дверей и материала полок. Несколько выбранных атрибутов всё ещё принадлежат соседним категориям; например «Вместимость винного шкафа (Отдельно стоящие холодильники)» требует отдельной проверки видимости/смысла.

## Проверки и воспроизведение

Независимые READ ONLY запросы подтвердили: оба канала неактивны; исходные соответствия, прочие строки/выражения и видимость сохранены; записаны именно первые прогоны; все кандидаты и непустые предложения принадлежат точной группе mainAttrGroup. Проверки записаны в verification обоих JSON.

Прошли 35 серверных тестов, включая точное ограничение группой, отклонение неизвестной/неоднозначной группы, allowlist категории и сохранность копии. TypeScript-проверка прошла. Транспортные тесты используют локальный фиктивный провайдер; SQL-тест — READ ONLY Kuppersberg.

```powershell
# Только метаданные, без LLM и записи в БД:
node -r ts-node/register/transpile-only scripts/ai-mapping/kuppersberg-sandbox.cjs --group=mainAttrGroup --metadata-only

# Сковороды, два прогона и сохранение первого в неактивной копии:
node -r ts-node/register/transpile-only scripts/ai-mapping/kuppersberg-sandbox.cjs --group=mainAttrGroup

# Винные шкафы:
node -r ts-node/register/transpile-only scripts/ai-mapping/kuppersberg-sandbox.cjs --group=mainAttrGroup --category=15450095
```

Прогоны с записью уже выполнены. Повтор остановится при существующем identifier, до запросов модели. Для нового независимого опыта нужен отдельный identifier и файл отчёта. Предварительный metadata-only режим можно выполнять повторно: он перезапишет только свой локальный отчёт.

Дополнительные артефакты: [shortlist сковород до LLM](kuppersberg-sandbox-1c-metadata.json), [поиск названий по всей группе](kuppersberg-1c-candidate-audit.json), [диагностика видимости связанных объектов](kuppersberg-1c-visibility-audit.json).

## Следующие шаги

1. Расшифровывать PIM-типы для модели: typeName и признак numeric вместо одного кода. Проверить фактические dictionary-флаги.
2. Загружать и разделять source.path и target.path. Для обычных атрибутов применять видимость объекта, для атрибутов зависимости — источник; отдельно покрыть стандартные поля и отсутствие связанных объектов.
3. Нормализовать формы слов и сокращения («цвета/цвет», «кол-во/количество»), исключать общие служебные слова из ранжирования. Сначала проверить наличие подтверждённых 1С-кандидатов в top-30.
4. Составить вручную проверенный 1С-эталон и повторить обе категории на неизменной выборке. Оценивать допустимые соответствия/отказы, стабильность и время отдельно.
5. Если ограничение группой полезно, добавить выбор группы в серверный API и интерфейс; сейчас эта настройка доступна только эксперименту.
