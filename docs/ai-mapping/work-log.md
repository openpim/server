Обновлено: 2026-10-08. Источник: выполненные изменения и результаты проверок в этой сессии.

## 2026-10-07 — постановка задачи

Пользователь запросил заполнение маппинга маркетплейсов по кнопке с настройками нейросети в серверном `.env`. Уточнили: нужны соответствия атрибутов, а не значения характеристик товаров. Для испытания выбран сервис с OpenAI-совместимым API.

Принятый сценарий: выбрать категорию → получить предложения → проверить → применить выбранные строки → сохранить канал.

## 2026-10-07 — первая реализация

В ходе сессии реализовали поддержку Wildberries (тип 2), Ozon (тип 3), Яндекс Маркета (тип 9).

Серверная часть:

- Настройки провайдера, модели, URL, ключа, формата ответа, пакетов и лимита времени.
- GraphQL-проверка доступности и получение предложений без сохранения маппинга.
- Авторизация, проверка прав канала и изоляция tenant.
- Загрузка актуальных характеристик через обработчик канала.
- Лексический отбор до 30 PIM-кандидатов для каждой характеристики.
- Отправка ограниченных метаданных, проверка JSON и допустимости идентификаторов.
- Последовательные пакеты, общий дедлайн и блокировка одновременных запросов на tenant в пределах процесса.

Интерфейс `web3`:

- Кнопка AI, таблица предложений, подтверждение и отмена.
- Заполнение только пустых `attrIdent` и `expr`.
- Сохранение существующих соответствий, выражений и параметров.
- Защита от устаревшего результата при смене категории и от перезаписи ручных изменений.
- Обязательная проверка числовых, словарных и потенциально преобразуемых соответствий.

На этом этапе прошли 21 серверный тест, 34 теста каналов интерфейса, TypeScript-проверка, целевой lint и сборка `web3`. Это исторический результат на версии того этапа.

## 2026-10-07 — подключение реального API и HTTPS

Провайдер: OpenAI-совместимый endpoint Ollama Cloud; использованная модель: `deepseek-v4.1-flash`, формат `json_object`.

Первый запрос столкнулся с `SELF_SIGNED_CERT_IN_CHAIN`. Проверка показала различие между доверенными сертификатами ОС и стандартным набором Node.js.

Добавили опциональное использование системных доверенных сертификатов только для AI-запросов. Проверку HTTPS-сертификатов сохранили включённой. Реальный синтетический запрос «Цвет → color» успешно завершился примерно за 2 секунды.

Проверка подтверждала транспорт и простой сценарий, а не качество на реальной категории.

## 2026-10-07 — исправление открытия MDM-маппинга

Пользователь сообщил: категория выбрана, но редактор маппинга не открывается в канале «Мастер каталог (3logic)».

Причина: компонент выбора категории слушал `change`, тогда как Vuetify 3 использует `update:modelValue`. Исправили обработчик в `web3/src/channels/mdm/MDMConfigComponent.vue`.

Добавили два регрессионных теста: открытие категории с сохранением соответствий и скрытие редактора при очистке выбора. Тесты воспроизвели ошибку до исправления и прошли после него. Все 36 тестов каналов и сборка интерфейса прошли.

Это исправление редактора MDM, а не добавление AI-маппинга в MDM. Для типа 6 AI-кнопка на этом этапе не подключена.

## 2026-10-07 — недопустимый идентификатор в ответе модели

Пользователь получил `Invalid PIM identifier in AI mapping response.`

Проверка кода установила: идентификатор вне списка кандидатов одной строки отклонял весь запрос. Конкретный ошибочный ответ модели на реальной категории не был получен для анализа; точный вариант её ошибки неизвестен.

Изменили обработку: недопустимое PIM-соответствие становится `null` с признаком проверки и пояснением. Корректные предложения остальных строк сохраняются. Неизвестные ID характеристик, дубликаты и неверная структура ответа продолжают отклонять операцию.

Добавили тесты, запрещающие выдуманные идентификаторы, кандидатов из чужого списка и угадывание по изменённой строке идентификатора. Прошли 23 серверных теста и TypeScript-проверка.

Реальный запрос на трёх синтетических характеристиках вернул два допустимых соответствия, включая языковой идентификатор, и `null` для неизвестной характеристики.

## 2026-10-07 — таймаут

Пользователь получил `AI mapping timeout. Try a smaller batch or increase OPENPIM_AI_TIMEOUT_MS.`

На момент проверки настройки были: общий лимит 60000 мс и пакет 20 характеристик. Лимит относится ко всем последовательным LLM-пакетам операции.

Для испытания изменили серверную конфигурацию:

```dotenv
OPENPIM_AI_TIMEOUT_MS=300000
OPENPIM_AI_MAPPING_BATCH_SIZE=5
```

Запрос на 20 синтетических характеристиках с 30 кандидатами на строку завершился четырьмя пакетами примерно за 8 секунд; получено 20 соответствий.

Это один успешный прогон. Причина длительности пользовательского запроса не измерена: нет записи его объёма, времени каждого пакета и нагрузки провайдера. Отсутствие таймаута на реальной категории после изменения настроек пока не подтверждено.
