# Видимость товаров и нормализация поиска кандидатов

Дата: 2026-10-08. Реализовано в серверной ветке `AIMappingAssistant`.

## Причины ошибок

В [тесте популярных маппингов](kuppersberg-popular.md) кандидаты из 1С отбирались из 917 атрибутов. Для категории, выбранной через связь, обычные атрибуты (`relations=[]`), стандартные поля и поля типа 9 не проверялись по путям товаров мастер-каталога. В результате поле варочной поверхности попадало в запросы для вытяжки и духовки.

При ранжировании использовались буквальные слова. «Цвета» не совпадали с «цвет», а «для» давало преимущество посторонним полям и могло вытеснить цвет из первых 30 кандидатов.

## Изменения

Контекст видимости теперь содержит отдельные `paths` источников и `targetPaths` связанных товаров:

- Обычные атрибуты, стандартные поля и атрибуты типа 9 проверяются по предкам путей товаров.
- Нестандартный атрибут с одной связью, совпадающей с выбранной связью категории, проверяется по исходным путям. Сохраняется поддержка нескольких источников одного товара.
- Другие и смешанные области связей сохраняются как неизвестные: их видимость нельзя достоверно вывести из единственной связи категории.
- Если путей товаров нет или старый вызывающий код их не передал, фильтр не угадывает целевую область. Категории без товаров требуют отдельной проверки.
- При выборе категории напрямую, без связи, прежняя проверка по её путям сохраняется.

`mappingVisibilityTargetsSQL` выбирает товары только через источники выбранного поддерева. Альтернативные источники одного товара не расширяют множество товаров для целевой видимости. Tenant и удаление проверяются у корней, источников, связей и товаров. Пути используются для фильтрации на сервере, не передаются модели.

Поиск теперь использует ограниченный словарь нормализации: формы цвета, размеров и материала, несколько английских названий, написания единиц. Служебные слова «для», «при», названия технических типов исключены, слова дедуплицируются. Числовой кандидат получает небольшой бонус для числовой характеристики. Это не полноценный морфологический или семантический поиск, не пересчёт единиц и не запрет всех пар с различными типами.

Изменения применяются к общему и построчному AI-запросу. GraphQL-ответ и клиентские кнопки не менялись. В приложении по-прежнему доступны все разрешённые группы; ограничение только группой 1С используется в операторском эксперименте.

## Проверки

Пять новых регрессионных тестов сначала воспроизвели ошибки: смешение целевых и исходных путей, несколько целевых категорий, цвет среди посторонних полей, размеры с типами и передача отдельного контекста через resolver. После исправления прошли все 48 целевых серверных тестов и `npx tsc --noEmit`.

SQL проверен на CTE-фикстурах внутри `READ ONLY`: исключены чужие tenant, удалённые корни/источники/товары/связи, другая связь; повторная связь не дублирует результат; альтернативный источник не добавляет посторонний товар.

Операторские скрипты первого теста, копии категории и вариантов справочников также передают целевые пути, чтобы новые запуски использовали текущие правила. Старые JSON-отчёты сохранены как история.

## Повторный тест Kuppersberg

Те же три категории и 30 строк, по два прогона. ID и весь контекст характеристик маркетплейса взяты из предыдущего отчёта и проверены по актуальным настройкам и API. Исходный маппинг модели не передавался. Сравниваются одновременно видимость и нормализация; вклад каждого изменения отдельно не измерен.

| Категория | Кандидатов до / после целевой видимости | Предложений до, два прогона | Предложений после, два прогона | Совпали ответы после | Совпали непустые пары после |
| --- | ---: | ---: | ---: | ---: | ---: |
| Варочные панели | 917 / 135 | 3 / 3 | 4 / 4 | 10/10 | 4 |
| Вытяжки встраиваемые | 917 / 75 | 3 / 2 | 3 / 4 | 8/10 | 2 |
| Духовые шкафы | 917 / 127 | 2 / 3 | 3 / 3 | 10/10 | 3 |

Это размеры полного допустимого пула группы 1С; в модель уходит до 30 кандидатов на строку. Время повторных вызовов: варочные панели 13,6/15,0 с, вытяжки 29,1/26,3 с, духовки 18,3/21,2 с. Ускорение не продемонстрировано.

### Что улучшилось

- `attr_TSvet9` («Цвет») присутствует в shortlist обоих полей цвета во всех трёх категориях. Раньше его там не было. «Цвет для фильтра» получил предложение в каждом из шести результатов.
- `attr_OsobennostiDizaina` больше не попадает в shortlist особенностей конструкции вытяжки и духовки. В обоих прогонах для этих строк получен отказ. Для варочной панели кандидат остаётся.
- Ширина и высота больше не переключаются между ID внутри каждой категории в двух выполненных прогонах.

### Что остаётся неоднозначным

- Для цвета вытяжки модель выбирает то общий цвет, то «Цвет вытяжки». Для маркетингового названия цвета один прогон отказывается, другой предлагает общий цвет. Нужно подтверждение смысла и допустимых значений.
- Общий LOV у 901 атрибута не подтверждает словарь конкретного поля. Два одинаковых ответа не доказывают правильность.
- Вес вытяжки сопоставляется с текстовым `attr_ves`; модель отмечает необходимость проверки типа/единиц. Преобразование текста в число не создаётся автоматически.
- Старые ссылки вне группы 1С не являются эталоном для прямого сравнения ID. Все непустые результаты требуют проверки.
- Выборка содержит много служебных полей и не включает обязательных характеристик. Для оценки качества техники её надо дополнить специфическими строками.

Повторяемость после изменений — 28/30, из них девять непустых пар и 19 отказов. До изменений — 27/30, из них шесть непустых пар и 21 отказ. Эти числа не являются точностью.

## Артефакты и использование

- [Результаты и независимая проверка пулов](kuppersberg-popular-filtered-evaluation.json).
- [Исходный отчёт до исправлений](kuppersberg-popular-evaluation.json).
- Повтор на фиксированных строках: `node -r ts-node/register/transpile-only scripts/ai-mapping/kuppersberg-popular-evaluate.cjs --compare-visibility`.
- Независимая проверка: `node -r ts-node/register/transpile-only scripts/ai-mapping/kuppersberg-popular-audit.cjs`.

База не менялась. Отдельное чтение подтвердило сохранность всего исходного маппинга. Аудит подтвердил шесть полных прогонов, одинаковый контекст маркетплейса, принадлежность кандидатов группе 1С и прохождение целевой видимости, допустимость всех предложенных ID.

Для проверки кнопок перезапустить сервер и открыть одну из трёх категорий. Применение предложения и сохранение маппинга остаются явными действиями пользователя.
