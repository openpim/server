# Тест самых используемых маппингов Kuppersberg

Дата: 2026-10-08. Канал `ym`, кандидаты только `mainAttrGroup` («Основные (из 1С)»). Провайдер и модель: Ollama Cloud, deepseek-v4.1-flash.

## Выбор категорий и характеристик

Пользователь поручил самостоятельно выбрать популярные маппинги и провести тест. Популярность определяли по числу уникальных PIM-товаров, соответствующих настройкам категории. Проверены все 72 настроенные категории; все имели поддерживаемый способ выбора по видимости.

Подсчёт повторяет критерии обработчика Yandex: tenant, активные записи, допустимый тип товара, поддерево видимости; при наличии связи — источник `ymcat_<categoryId>` и нужный relationId. Подсчёт не измеряет продажи, фактические выгрузки или заполненность характеристик. Для категорий с выражением без видимости скрипт не исполняет код и оставляет число товаров неизвестным.

Следующие по распространённости: обычные вытяжки — 63, отдельно стоящие холодильники — 60, встраиваемые посудомоечные машины — 51.

Для каждой категории взяли десять актуальных характеристик без выражений и дубликатов. Приоритет — частота прямого маппинга ID характеристики в разных категориях, затем обязательность. В выбранных строках обязательных характеристик нет. Служебные поля встречаются чаще специализированных: количество упаковок, миниатюра, прочие характеристики и дополнительная информация настроены в 72 категориях, название группы вариантов — в 71; два поля цвета — в 61, ширина — в 57.

Это проверка наиболее повторяющихся полей популярных категорий, а не полный тест специфических характеристик техники. Частота настройки также не доказывает заполненность значения у товара.

## Методика

- По два независимых вызова `suggestMappings` на одинаковом контексте каждой категории: всего 30 строк и 60 результатов.
- Кандидаты, типы, видимость и shortlist — текущий алгоритм приложения. Обогащение явными типами и примерами справочников включено; по три загруженных словаря маркетплейса на категорию.
- Модель не получает исходный маппинг. Существующий маппинг сравнивается локально после ответа.
- Исходные соответствия всех 30 строк используют атрибуты вне shortlist группы 1С. Поэтому совпадение ID с оригиналом не измеряет качество нового маппинга из 1С.
- Значения товаров не выбирались и не отправлялись модели. Транзакции чтения — `READ ONLY`, изменений БД нет.

## Проблемы и выводы

1. **Цвет теряется до модели.** Оба поля цвета дали отказ во всех категориях. В предыдущем аудите группы найден `attr_TSvet9`, но в текущих shortlist этих строк его нет. Нельзя считать отказ доказательством отсутствия атрибута цвета в PIM. Нужны нормализация словоформ и проверка полноты поиска.
2. **Одно название допускает разные поля.** Для ширины варочной панели модель переключилась с `attr_SHirinaSm2` («Ширина, см варки») на `attr_SHirinaSm4` («Ширина, см»). Типы одинаковые, одних названий недостаточно для уверенного выбора. Нужна проверка области видимости целевого каталога.
3. **Признак другой техники попадает в предложение.** `attr_OsobennostiDizaina` описывает особенности дизайна варочных поверхностей. Для вытяжки первый прогон предложил его, второй отказался; для духового шкафа — наоборот. Во втором ответе для духовки модель прямо признаёт другую категорию, но всё же возвращает кандидат с флагом проверки. Флаг проверки не устраняет проблему состава shortlist.
4. **Общий LOV остаётся слабым свидетельством.** Наличие примеров в общем словаре не подтверждает домен конкретного поля. Сейчас 901 атрибут используют этот LOV; совместимость значений отдельно не доказана.
5. **Служебные поля требуют отдельной обработки.** Отказы для миниатюры, группы вариантов и свободного текста относятся к переданным кандидатам 1С. Для них может требоваться другая группа, стандартное поле или выражение; полного отсутствия аналога в PIM этот тест не устанавливает.

Приоритет следующего изменения: корректная видимость по целевой категории и нормализация поиска. Затем повторить на зафиксированных строках; дополнить выборку обязательными и специализированными характеристиками трёх категорий, чтобы частота служебных полей не скрывала качество маппинга техники. Стабильные пары сохранять как память только после подтверждения.
